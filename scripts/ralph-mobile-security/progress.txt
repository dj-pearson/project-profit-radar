## Consolidated Patterns

### Auth Architecture
- AuthContext.tsx manages all auth state, session monitoring, and login/signup flows
- Login brute force protection in src/lib/security/loginProtection.ts (5 attempts, exponential backoff)
- Client-side rate limiting in src/lib/security/rateLimiter.ts (Token Bucket algorithm)
- CSRF infrastructure wired to auth forms (SignIn, SignUp) via CsrfTokenField and verifyCsrf() in Auth.tsx
- Session monitoring: 5-minute validity checks, 30-minute inactivity timeout
- OTP flows handled via edge functions: send-auth-otp, verify-auth-otp, reset-password-otp

### Edge Functions
- Use `getCorsHeaders(req)` from `_shared/secure-cors.ts` for whitelist-based CORS
- Use `checkRateLimit()` from `_shared/rate-limiter.ts` for rate limiting
- Use `getClientIP(req)` from rate-limiter.ts for consistent IP extraction
- Auth pattern: service role client with SUPABASE_SERVICE_ROLE_KEY
- Input validation: Zod schemas
- Password validation: server-side enforcement via _shared/password-policy.ts (validatePasswordStrength)

### Security Gaps Identified (Remaining)
- No MFA enforcement during login
- No session invalidation on password change
- No account lockout recovery mechanism
- No per-email rate limiting on OTP verification attempts
- No device fingerprinting or trust system
- No step-up authentication for sensitive ops
- Auth form inputs missing maxLength attributes

### Build Verification
- `npm run build` must pass (TypeScript + Vite build)
- `npm run lint` must pass (ESLint)
- Edge functions in supabase/functions/ use Deno imports (esm.sh, deno.land)
